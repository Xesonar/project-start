## 🟠 SHOULD HAVE (24–48 часов)

### ✅ 1. Публичное портфолио по ссылке — «бизнес-эффект» №1

**Сделано.** Ценность продукта двойная: студенту — подтвердить опыт,
работодателю/преподавателю — проверить. Ссылка = виральность: каждая
отправленная ссылка распространяет продукт.

**Что реализовано:**
- `models/user.py`: `portfolio_slug` — миграция `e7b2c9d5f130`, уникальный
  индекс, nullable (приватность по умолчанию).
- `services/portfolio.py`: транслитерация имени в читаемый слоган
  (`alisа-ivanova → alisa-ivanova-a1b2`), защита от коллизий, сборщик
  публичной вьюхи.
- `POST /me/portfolio/link` — создаёт слаг, идемпотентно.
- `GET /p/{slug}` — **без авторизации**, отдаёт только опыт: навыки, роли,
  результаты, кто подтвердил. Никаких контактов.
- `screens/PublicPortfolio.tsx` — отдельная публичная страница,
  скелетоны, 404-стейт, кнопка «Поделиться» (MAX Bridge → нативный шер /
  clipboard fallback).
- На экране «Портфолио» — карточка «Отправить работодателю»: создаёт ссылку,
  копирует в буфер, даёт «Открыть →».
- Тесты покрывают создание и идемпотентность ссылки, пустое портфолио, 404,
  требование авторизации, полный цикл завершения и состав публичной выдачи.

**Момент для защиты:** публичная ссылка открывается на телефоне без авторизации.

### 2. Живая команда: кто ещё идёт на проект

**Почему:** «Один отклик — страшно». Видеть, что двое уже подали на эту же
роль, — социальное доказательство и FOMO.

**Реализация:** `GET /projects/{id}` вернуть `applicants_count` и
`role_applicants: {role_id: count}` (один `GROUP BY` запрос, не exposing
личностей). На экране роли: «2 человека уже откликнулись».

### 3. Геймификация: XP и уровни за завершённые проекты

**Почему:** retention и «эмоция от прогресса». Для хакатона — красивый
момент «level up».

**Реализация:** `models/user.py` добавить `xp` (int, default 0).
`services/applications.py` при подтверждении участия начислять XP по
сложности проекта (beginner 30 / intermediate 60 / advanced 100).
`GET /me` отдаёт `xp` и `level` (уровень = пороги 0/100/250/500).
На «Главной» — прогресс-бар до следующего уровня + конфетти при level-up
(`canvas-confetti`, ~3 КБ). **Безопасно:** начисление только при
подтверждении организатором, накрутить самому нельзя.

### ✅ 4. Тёмная тема приложения

**Почему:** показ на проекторе в светлой аудитории и корректное отображение в
системной теме устройства/MAX.

**Сделано:** тема следует системной настройке, сохраняет ручной выбор и имеет
переключатель на главной. Базовые компоненты и формы адаптированы к обеим темам.

### 5. Реальные уведомления

**Сделано в коде:** счётчик на вкладке и MAX-сообщение при смене статуса.
**До сдачи:** зарегистрировать webhook и проверить уведомление реальным клиентом MAX.

## 🟢 NICE TO HAVE (roadmap для питча)

### AI-ментор по навыкам
На гэпах из MatchRing — кнопка «Что учить?» → LLM генерирует пошаговый
мини-план (2 недели, 3 шага, бесплатные ресурсы). Промпт в `ai_client.py`,
структурированный JSON, fallback на заглушки. **Это то, что превращает
«не подходишь» в «вот путь» — главная идеологическая фича.**

### Карта роста (radar-chart навыков)
SVG-радар по категориям навыков студента vs. требования рынка (из пула
проектов). Визуализация данных = +баллы за техничность.

### Telegram-зеркало бота
Вся логика чат-бота вынесена в pure-функции (`bot/screens.py` уже такие) —
двойной фронтенд для Telegram занимает ~1 день.

### Расписание/дедлайны в календарь
Кнопка «Добавить в календарь» (`.ics` из `project.deadline`) — мелочь,
которая показывает заботу.

### Аналитика для вузов
Агрегат: сколько студентов с какого курса, какие навыки востребованы vs.
имеются. Продажа B2B — это уже бизнес-модель для пост-хакатона.

### Realtime
SSE/WebSocket для live-обновления статуса заявок и состава команды без
перезагрузки. Сейчас — polling при открытии экрана, этого хватает.
